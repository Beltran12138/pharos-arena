# Doc-Search CLI

`pharos-docs`: ask the Pharos docs a question from the terminal. It goes through the **Developer Docs MCP**
server (`https://docs.pharos.xyz/~gitbook/mcp`) and prints a short answer with the pages it came from, or
says plainly that the docs don't cover it.

## Install

```bash
git clone https://github.com/Beltran12138/pharos-arena && cd pharos-arena
npm install
npm link            # optional: puts `pharos-docs` on your PATH
```

Without `npm link`, run `node doc-search-cli/pharos-docs.mjs "…"`. Node 20+.

## Usage

```bash
pharos-docs "how do I deploy a contract?"      # concise answer (first 14 lines) + sources
pharos-docs --full "how do I deploy a contract?" # whole answer, up to 10 sources
pharos-docs --search "chainlink price feed"      # matching pages only, no synthesis
```

Exit code `0` = answered, `3` = the docs don't cover it, `1` = error. Scripts can branch on that.

## How it decides what to show

- The answer comes from Docs MCP `askQuestion`; `--search` uses `searchDocumentation`.
- **Sources:** pages the answer links to inline are listed first (those are what it actually used), then
  the rest of the source list. Docs MCP's own list sometimes includes unrelated pages (e.g. *Validator Node
  Deployment* for a contract-deployment question), so the inline citations are the better signal.
- **"No good answer":** when the answer says the documentation does not provide, cover or describe the
  thing asked, the CLI prints `✗ The Pharos docs don't answer this.`, shows the closest pages labelled as
  *not* answering it, and exits with 3. It never fills the gap itself.
- Long answers are cut at 14 lines without leaving a code block open.

## Examples (real runs)

Answers are generated by Docs MCP, so wording varies between runs. Full outputs in [`examples/`](examples/).

**1. `pharos-docs "what is the chain id and RPC of Pharos mainnet?"`**

```
Pharos Pacific Mainnet uses **Chain ID `1672`** and RPC URL **`https://rpc.pharos.xyz`**. See [Pacific Mainnet](/getting-started/network/pacific-mainnet).

Sources:
  - Pacific Mainnet: https://docs.pharos.xyz/getting-started/network/pacific-mainnet
  - Node Debugging & Configuration: https://docs.pharos.xyz/node-and-validator-guide/node-debugging-and-configuration
  - RPC Infrastructure: https://docs.pharos.xyz/tooling-and-infrastructure/rpc
  - Cross Chain Infrastructure: https://docs.pharos.xyz/tooling-and-infrastructure/cross-chain
```

**2. `pharos-docs "how do I use Chainlink price feeds on Pharos?"`** (excerpt)

```
For a contract that needs the latest price, use Pharos's **Chainlink Push Engine Feeds**. Each pair has a proxy exposing `latestAnswer()`.
On Pacific Mainnet, for example, the ETH/USD proxy is `0x1Ed3e8CdC173363593BfAD9bF77aa2A0e7351DB8`. Feed values use **18 decimals**.
…
Sources:
  - Chainlink Push Engine Feeds: https://docs.pharos.xyz/tooling-and-infrastructure/oracles/chainlink-pe
  - Chainlink Data Feeds: https://docs.pharos.xyz/tooling-and-infrastructure/oracles/chainlink-ds
```

**3. `pharos-docs "how do I stake ETH on Lido from Pharos?"`** — not covered, exit 3

```
✗ The Pharos docs don't answer this.

  Pharos documentation doesn't provide steps for staking ETH through Lido directly from Pharos. …

Closest pages (they do not answer it):
  - About Pharos: https://docs.pharos.xyz/introduction/readme
  - Node Management: https://docs.pharos.xyz/node-and-validator-guide/node-management
```
